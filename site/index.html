How it works

Four steps, no API key in sight

terr never talks to an AI provider directly. It talks to a small shared backend, which is the only place your key ever lives — so anyone can install terr without owning any credentials. Keep scrolling to see the whole path.

Anything from a missing package to a broken Docker port.

3

It asks an AI model to explain the error and the fix.

You get plain English

Cause, fix steps, and copy-ready commands, in your terminal.

FAQ

Good to know

Do I need my own API key?

No. terr talks to a shared backend that holds the key for you. That's the entire reason the backend exists — so nobody installing terr has to own or pay for their own AI access.

What languages and tools does it understand?

Anything that prints a readable error to stdout or stderr — Python, Node, Docker, Git, and most common CLI tools. It detects the environment from the error text itself, no flags needed.

Is my error log stored anywhere?

terr sends the error text to the backend for translation and nothing more — check with whoever is hosting your backend instance for their specific retention practice.

Does it work offline?

No — translating an error requires a round trip to the backend, so you'll need an internet connection for terr to respond.

Can I self-host the backend instead?

Yes. The backend is a small open server — point TERR_ENDPOINT at your own deployment and terr will use it instead of the default.
